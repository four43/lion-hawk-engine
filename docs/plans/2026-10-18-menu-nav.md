# Lion Hawk: controller menu navigation (plan, 2026-10-18)

Make every menu in Rally and Tractor Pickup navigable with a gamepad and the keyboard. This is research option C (`docs/research-menu-navigation.md` §4): view-side DOM focus with spatial scoring, plus a small sim-side contract per overlay. The user's decisions are in §7 of that doc. The target is engine 0.12.0, built on the current unreleased `main` (after ba7c59e).

## Behaviour

**Buttons (standard mapping, Xbox-style; no Nintendo swap):**

| Input | In a menu (a `nav` overlay is on top) | In gameplay |
|---|---|---|
| D-pad / left stick / arrow keys | Move focus one step per push, with no repeat and no wrap | Game bindings |
| A / Enter | Activate the focused control (click it; press and release for holds) | Game bindings |
| B / Esc | **Back:** run the top overlay's `back` | Esc: game's `pause`; B: game bindings |
| Start | Back (closes the menu) | Opens the overlay whose `nav.open` names it (tap or hold, per menu) |
| LB / RB | Step the nearest `choice` group to the previous or next option | Game bindings |

- **Stick:** a push is the dominant axis crossing 0.5. It re-arms once both axes are back under 0.3, so one flick moves exactly one step.
- **Focus ring:** shown only while the last input came from a pad or keys (`<html data-lh-input="pad|keys|pointer|touch">`). Focus uses `focus({ focusVisible: true })`, so the ring shows even after a mouse click.

## Spec additions (`docs/spec.md` §5.3–5.4)

- **[U-7] Menu navigation.**
  - `bindMenuNav(engine, opts)` (view) moves real DOM focus among candidates.
  - Candidates are the focusable, enabled, visible `button`s and `[data-lh-nav]` elements in scope. Registered and unregistered buttons both count, because Tractor's swatches and pages are plain buttons.
  - Text inputs are skipped until there's a pad text-entry answer (see Deferred).
  - Moving picks the best candidate with the pure scorer [U-8].
  - Per-element overrides: `data-lh-nav-up|down|left|right="<testid>|none"`.
  - Focus scrolls into view with `block: 'nearest'`.
- **[U-8] Scorer.** `pickNeighbour(from, dir, rects)` is a pure function over `{ x, y, w, h }` rects, exported from `lion-hawk/sim` so Node tests it without layout.
  - It rejects candidates whose centre isn't past the moving edge.
  - It scores by primary distance and cross-axis offset (Norigin/Projection style), with a bonus when the candidate overlaps on the cross axis.
  - Ties go to document order. It returns `-1` at an edge (no wrap).
- **[U-9] Overlay `nav` options** (scene sim half): `nav: { modal = false, initial, back, input = 'menu', open }`.
  - **`open: { button, key, seconds = 0, when }`** is how the menu is summoned from gameplay.
    - `button` is a pad button name (`'start'`, `'select'`, …) and `key` is a keyboard key (`'escape'`).
    - `seconds` is the press duration: 0 means a tap opens it, >0 means it must be held that long (a child lock).
    - `when` is an optional gate `(engine) => boolean`.
    - The view measures the hold on engine time [U-5] and issues the engine-reserved command `lh.open { name }`; the built-in handler checks `when` and calls `engine.overlay(name, undefined, { once: true })`, so it's recorded and replayable.
    - Two overlays may share a button with different durations (a tap for one, a hold for the other). A tap fires on release when a longer hold on the same button exists, so the hold never opens the tap menu first.
  - **`modal`** scopes the search to this overlay. Non-modal overlays search themselves first and fall back to the scenes below. This is separate from `pauses`.
  - **`initial`** is the testid focused when the overlay opens. After that, focus returns to the last focused control when the overlay is uncovered again, then to the first candidate.
  - **`back`** is an action name or `(engine, ctx) => void`.
    - The view issues the engine-reserved command `lh.back`, so it is recorded and replayable.
    - A built-in game-wide handler runs the topmost open overlay's `back`. No handler means a no-op.
    - Back is flow, so it lives in the sim [S-4]. Headless tests use `h.command('lh.back')`.
  - **`input: 'menu' | 'shared'`.**
    - `'menu'`: while the overlay is topmost, game device bindings on the pad and keyboard are released and ignored (the [I-3] release path, so held gameplay buttons let go cleanly), and the navigator owns them.
    - `'shared'` (small sub-menus): game bindings stay live. Navigation uses only the D-pad and arrow keys, plus A/Enter on a focused control, so such a game shouldn't bind those in gameplay.
- **[I-8] Pad edges.** The navigator's pad reader shares `bindGamepad`'s injectable `getGamepads`.
  - It produces rising edges for the D-pad, the stick-as-D-pad, A, B, Start, LB and RB, with no repeat.
  - It doesn't allocate per frame [R-8] and counts on `update(dt, raw)` [U-5].
- **[U-10] Glyphs.** `<span data-lh-glyph="confirm|back|menu|move|prev|next">` names a *role*, not a button. It shows that role's icon for whichever input was used last, with proper art for every input the engine supports:

  | Family | Detected from | Source set (Kenney Input Prompts 1.5A, CC0, Vector) |
  |---|---|---|
  | `xbox` | standard pads by default, Microsoft vendor `045e`, "Xbox" in `Gamepad.id` | Xbox Series |
  | `ps` | Sony vendor `054c`, "DualShock", "DualSense" or "PlayStation" | PlayStation Series (PS5 art) |
  | `deck` | Valve vendor `28de`, "Steam Deck" | Steam Deck |
  | `generic` | a pad without standard mapping, or an unknown vendor | Generic |
  | `keys` | last input from the keyboard | Keyboard & Mouse (Enter, Esc, arrows) |
  | `pointer` | last input from the mouse | Keyboard & Mouse (mouse left) |
  | `touch` | last input from touch | Touch (finger tap) |

  - Games can turn prompts off per family with CSS on `data-lh-input`; for example, Rally may hide them on touch, where the buttons speak for themselves.
  - A role a family doesn't have (no Back key on touch) hides its span.
  - The kit ships a curated subset (the roles above, plus D-pad and stick art) as `lion-hawk/kits/glyphs`, with Kenney's licence alongside. It's copied from the All-in-1 pack (`~/Downloads/Kenney Game Assets All-in-1 3.7.0/Icons/Input Prompts`), not the whole 600-file set.

## Engine tasks

1. **Scorer** (`src/core/navScore.js`) with the thorough unit tests (decision 10):
   - rows and columns;
   - a grid;
   - Rally's diagonal footer (Settings · best · Drive);
   - uneven sizes and overlapping rects;
   - candidates behind the edge;
   - an edge returning `-1`;
   - ties going to document order.
2. **Pad edge reader** (`src/view/padEdges.js`): stick hysteresis, D-pad and button edges, one step per push. Unit tests use a fake `getGamepads`.
3. **Overlay `nav` contract** (`src/core/engine.js`, `actions.js`):
   - validate the options;
   - the `lh.back` command and handler;
   - the `lh.open` command and handler (the `when` gate, `once`), and the view's tap/hold timer for `open` (on engine time, a tap firing on release when a hold shares its button);
   - topmost-overlay lookup;
   - `input: 'menu'` gating in the device merge, releasing held levels on entry.
   - Headless tests:
     - back closes the top overlay only;
     - back with no handler is a no-op;
     - gating releases a held throttle and blocks new presses;
     - `lh.open` respects `when`, and a 2 s hold on engine time opens while a 1.9 s one doesn't;
     - `'shared'` leaves bindings live;
     - replay reproduces a back.
4. **DOM navigator** (`src/view/menuNav.js`):
   - scope (modal, fall-through);
   - candidates;
   - overrides;
   - activation, with holds pressed for as long as A is held, so Tractor's 1 s and 5 s holds still take holding;
   - LB/RB on choice groups;
   - initial focus and restore (subsumes most `view.focus` calls and fixes field note #113);
   - the arrow/Enter/Esc keyboard path;
   - `data-lh-input`.
   - A happy-dom test with an injected rect provider covers the wiring; the geometry is covered by task 1.
5. **Glyph kit** (`src/kits/glyphs/`): the SVG subset for all seven families, `glyphFor(role, family)`, `familyOf(gamepad)`, and the `data-lh-glyph` sync in the navigator. Unit tests check every role resolves (or is deliberately absent) for every family, and the detection strings.
6. **Boot wiring:** `boot` creates the navigator when the game has any `nav` overlay (opt-out `nav: false`), and it's exposed on `window.engine` for Playwright.
7. **Docs:** spec IDs above, field notes #138+ (marking #9, #18 and #113 resolved), CHANGELOG 0.12.0, and a version bump. Tag `v0.12.0` only with your OK.

## Game tasks

**Rally** (`games/rally`):

- **Overlay `nav` options:**

  | Overlay | `modal` | `initial` | `back` |
  |---|---|---|---|
  | `title` | yes | `title.drive` | none |
  | `settings` | yes | its first row | closes the sheet |
  | `pause` | yes | `pause.resume` | resumes |
  | `results` | yes | `results.retry` | to the main menu (`results.menu`) |

  All four use `input: 'menu'`.
- **Results** keeps its three buttons (Retry, New seed, Menu); B goes back to the main menu, same as the Menu button.
- **Pause opens through `nav.open`**: `{ button: 'start', key: 'escape', seconds: 0, when: running }`. That replaces the hand-rolled `pause` handling in gameplay; the existing `pause` action stays for the touch pause chip.
- **Pad A is no longer `confirm`** (`src/devices.js`, field note #16). The title's A drives only through the focused Drive button, which fixes the A double-fire. Enter stays `confirm` for keyboard players who never move focus.
- Start/Esc keep opening pause in gameplay.
- Glyph prompts in the title and pause footers (A Drive / B Back).
- **Tests:** `game.mjs` back/modal checks headless, plus one mobile-suite pass that walks title → settings → back → drive with a fake pad.

**Tractor Pickup** (`games/tractor-pickup`):

- **Parent menu opens through `nav.open`**: `{ button: 'start', seconds: 2 }`, the same 2 s child lock as the gear hold, which stays for touch.
- **`nav` on all eight overlays:**
  - `paint`, `book`, `parent` and `multiplayer`: `back` closes them.
  - `show`, `reward` and `sleep`: no `back`. The skip and wake holds are focused and held with A.
  - `start`: initial `start.go`.
- Tractor's plain-button menus become navigable with no change to their markup, because candidates are DOM buttons.
- **Tests:** a fake-pad walk of paint and book in its browser suite.

## Resolved questions (user, 2026-10-18)

1. **Opening a menu has a per-menu press duration** (`nav.open.seconds`), so a menu can open on a tap or a hold. Tractor's parent menu uses a 2 s Start hold.
2. **Rally results:** Retry plus a button back to the main menu (`results.menu`, already there). B goes to the main menu.
3. **Glyphs live once in the engine,** with proper art for every supported input family (table in [U-10]).
