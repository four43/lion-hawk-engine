### Task 1: Carry-over: setup and the start enter go through the transition queue

- The request-time duplicate check for `overlay(name)` projects the queue. Starting from the current stack, it replays the pending requests: `close x` removes x; `go y` makes y the only open scene; `overlay x` adds x. It throws `engine: scene '<name>' is already open` only if `name` would still be open at that point.

### Task 2: Per-source device layers (`src/core/actions.js`)

**Interfaces:**
- `input.device(partial, source = 'default')` keeps a separate partial for each source.
- Merging the sources in `apply()`:
  - an axis takes the value with the largest absolute size across sources, with ties going to the first registered source;
  - a button is the OR of all sources;
  - the source layers count as one "device" layer, which still sits under `set` and `hold`.
- `input.clearDevice(source)` removes that source's partial, for example when a pad disconnects.
- `apply()` must still allocate nothing. Keep sources in an array of `{ name, values }` in first-registration order.
- `device(partial)` with no source behaves exactly as before.

### Task 3: The rAF driver (`src/view/driver.js`) and the happy-dom test setup

**Interfaces:**
- `createDriver(engine, { raf, caf, doc, devices = [] })`. `raf`, `caf` and `doc` default lazily to the globals.
- It returns `{ start(), stop(), manual(on?) → boolean, get running, get manual, devices }`.
- **`tick(ts)`:**
  1. `dt = last === null ? 0 : (ts - last) / 1000`; then `last = ts`.
  2. For each device, call `device.update?.(dt)`.
  3. If not manual, call `engine.frame(dt)`.
  4. If manual, call `engine.render(engine.loop.alpha)`. The engine exposes `render(alpha)`, which calls the `onRender` callback without stepping.
  5. Schedule the next `raf`.
- **Visibility ([R-5]):** when `doc.visibilityState` becomes `'hidden'` (on `visibilitychange`), stop scheduling. When it becomes `'visible'`, set `last = null`, call `engine.loop.reset()` and resume if the driver was running.
- **`manual(true)`** stops stepping but keeps rendering. `manual()` with no argument returns the current state.
- Add `render(alpha)` to the core engine: `engine.render(alpha)` calls the current `onRender` function. Add a test for it in `test/engine.test.mjs`.

### Task 4: Keyboard and gamepad devices (`src/view/keyboard.js`, `src/view/gamepad.js`)

**Interfaces:**
- **`bindKeyboard(engine, bindings, { target, doc, source = 'keyboard', ramps = {} })`:**
  - `bindings` maps a lowercased `e.key` to `'action'` (a button) or `['axisAction', sign]`, for example `{ w: ['throttle', 1], arrowup: ['throttle', 1], s: ['throttle', -1], a: ['steer', -1], d: ['steer', 1], h: 'horn', ' ': 'handbrake' }`.
  - Listens for `keydown`/`keyup` on `target` (default `window`).
  - Ignores key-downs whose event target is inside `input, textarea, select, [contenteditable]`. Calls `preventDefault()` for bound keys. Ignores `repeat` key-downs for the held set (no change).
  - **`update(dt)`:**
    - The axis target is the clamped sum of the signs of held keys.
    - With `ramps[axis] = { rise, fall }`, the axis value moves toward the target at `rise`/s, and at `fall`/s when returning to 0 or crossing it. Without a ramp it jumps.
    - Then writes `engine.input.device({ ...all bound actions }, source)` into a reused object.
  - `release()` clears held keys and ramp values. It is called on `blur`, on `pagehide` and when `doc.visibilityState` becomes `'hidden'` ([I-3]).
  - Returns `{ update, release, dispose }`. `dispose` removes the listeners and calls `input.clearDevice(source)`.
- **`bindGamepad(engine, map, { getGamepads, source = 'pad' })`:**
  - `map` is `{ axes: { 0: ['steer', 1], 1: ['throttle', -1] }, buttons: { 0: 'horn', 7: ['throttle', 1] }, deadZone = 0.15 }`.
  - **`update()`:**
    - Polls `getGamepads()` (default `navigator.getGamepads?.() ?? []`).
    - Each axis gets a radial-style per-axis dead zone, `|v| <= dz` → 0, otherwise `sign * (|v| - dz) / (1 - dz)`, then is multiplied by its sign.
    - An analog button mapped to an axis contributes `value * sign`.
    - A button mapped to a button action is `pressed`.
    - Across pads, an axis takes the largest absolute value and buttons are OR'ed.
    - Writes `device(..., source)`. With no pads it calls `clearDevice(source)`.
  - Returns `{ update, dispose }`.

### Task 5: Touch devices (`src/view/touch.js`)

**Interfaces:**
- **`bindStick(engine, { root, x, y, radius = 70, edge = 24, deadZone = 0.1, source = 'stick', doc, ignore = 'button, [data-lh-ui] *' })`:**
  - A floating thumb stick that starts wherever a pointer goes down on `root`. It does not start within `edge` px of the left edge (Safari back swipe), or on elements matching `ignore`.
  - `x` and `y` are `[action, sign]`; screen right is +x and screen up is +y.
  - The stick vector is clamped to `radius`, then a radial dead zone is applied (Tractor Pickup's `radial()`), then it is written with `device({ [x[0]]: vx * x[1], [y[0]]: vy * y[1] }, source)`.
  - Tracks one `pointerId`. Listens for `pointermove`/`pointerup`/`pointercancel` on `root`'s owner window, routed by `pointerId`, following the research's iOS advice.
  - `lostpointercapture` counts as a release, and so do `blur`/`pagehide`/hidden.
  - Renders `<div class="lh-stick"><div class="lh-knob"></div></div>`, appended to `root`. It is hidden when idle, positioned at the pointer-down point, and the knob is translated.
  - Returns `{ dispose }`.
- **`bindHold(engine, el, action, { source = 'hold:' + action })`:**
  - `pointerdown` on `el` → `device({ [action]: true }, source)` and `setPointerCapture`.
  - `pointerup`/`pointercancel`/`lostpointercapture` and page hide → `false`.
  - `contextmenu` → `preventDefault`.
  - Returns `{ dispose }`.

### Task 6: DOM UI, `window.engine`, and boot with view halves

**Interfaces:**
- **`createUiDom(engine, { root, doc })`:**
  - **`sync()`:**
    - Reconciles `engine.ui.tree()` into `root`, keyed by test ID. Containers are `div[data-lh-ui=<scene>]`, with `data-lh-overlay` on overlay scenes, in stack order.
    - Buttons get `textContent = label`, `disabled` from `!enabled`, and `aria-pressed` for switches.
    - Removed controls are removed and new ones created. When nothing changed it does no DOM writes and no allocation beyond `tree()`.
    - Sets the `<html>` `data-lh-scene` and `data-lh-overlays` attributes.
  - A click on a control calls `engine.ui.tap(id)`. Errors (disabled or covered) are swallowed, because the DOM's `disabled` attribute already prevents most clicks.
  - Returns `{ sync, dispose }`. `boot` calls `sync()` after every transition (engine `scene`/`overlay` events, via `engine.events.on`) and once per frame.
- **`installEngine(engine, { driver, target, errors })`:**
  - Builds the full D-4 hook through `installEngineHook(api, { game: engine.game.id, target })`. `api`:
    - `ready`: a resolved Promise, or the one from `boot`;
    - `seed`; `errors` (an array); `manual(on)` → `driver.manual(on)`;
    - `stepN`, `advance`, `render(alpha)`; getters for `time` and `scene`;
    - `go`, `overlay`, `close`, `jump`;
    - `on(type, fn)` → an `engine.events.on` filter, returning the unsubscribe;
    - `events: { since(seq) }`. Events are returned as JSON-safe copies, with object and function values replaced by `{ id, kind }` when present, or dropped;
    - `state()`; `input: { set, hold, release, read: () => engine.input.values() }`;
    - `settled()`: true when no transition is queued and no `data-lh-state="opening|closing"` element exists in the target's document, if there is one;
    - `ui: { tree, tap }`; `rng`; `debug`: `engine.game.debug?.(engine) ?? {}`.
  - `errors` collects `error` and `unhandledrejection` events from `target`, plus anything boot catches.
- **`defineView({ scenes })`:** view halves keyed by scene name, `{ enter(engine, view), exit(engine, view), frame(engine, alpha, view) }`. `view` is the object `boot` passes in: `{ root, doc, ui, driver }`. Hooks are optional.
- **`boot(game, view, { root, doc, target, seed, scene, args, flags, devices })`:**
  - Parses `flags` (default `parseFlags(location.search)`), with seed from `flags.seed ?? seed ?? 1`.
  - Creates the engine, the driver (with `devices` built by caller-provided functions `(engine) => device`) and the UI DOM, then calls `installEngine`.
  - Wires view halves: on each scene/overlay event it calls the view half's `enter`/`exit`; it also calls them once for the start scene. `engine.onRender(alpha)` calls `frame` for the main scene and the open overlays, then `ui.sync()`.
  - With `flags.lhTest` it starts in manual mode and adds the stylesheet `*{transition:none!important;animation:none!important}` ([D-6]). Otherwise the driver starts.
  - Returns `{ engine, driver, ui, hook }`.

### Task 7: Playwright helpers and an end-to-end example

**Interfaces:**
- `testing/playwright.js`, exported as `lion-hawk/playwright`:
  - **`presets`:** objects `{ viewport, deviceScaleFactor, isMobile, hasTouch, userAgent?, safeArea: { top, right, bottom, left } }` for `'iPhone SE'`, `'iPhone 15 Pro landscape'`, `'iPhone 15 Pro portrait'`, `'iPad Pro 11 landscape'` and `'desktop'`. Take the safe-area values from Rally's `test/mobile.mjs` in the main checkout (read-only).
  - **`launch({ headless = true } = {})`:** finds Chromium for the installed `playwright-core` (use `chromium.executablePath()` first, then fall back to the newest `~/.cache/ms-playwright/chromium-*/chrome-linux*/chrome`). Launches with `--use-angle=swiftshader --enable-unsafe-swiftshader`. Returns `{ browser, close }`. If no Chromium is found, it throws `playwright: no chromium found (run npx playwright-core install chromium)`.
  - **`openGame(browser, url, { preset = 'desktop', seed, scene, query = {}, settings })`:**
    - Opens a context with the preset and `serviceWorkers: 'block'`.
    - Seeds `localStorage` via `addInitScript` when `settings` is given.
    - Injects the safe area as `--lh-sa-*` CSS variables.
    - Navigates to `url?lh-test&seed=…&…`, then waits for `window.engine` and `engine.ready`.
  - **The `game` driver** returned by `openGame`. Each method is one `page.evaluate`:
    - stepping and state: `step(n, input?)`, `seconds(s, input?)`, `until(fnSource, { maxSteps })`, `untilEvent(type, { maxSteps })`, `render()`, `state()`, `scene()`;
    - scenes and input: `go`, `jump`, `input.hold`/`release`;
    - UI: `tap(testid)` does a real Playwright `click` or `tap` on `[data-testid=…]`, depending on the preset;
    - **`touch`**, through a CDP session (`Input.dispatchTouchEvent`):
      - `start(id, target)` and `move(id, target)`, where `target` is a selector, `{ x, y }`, or `{ world: [x, y, z] }`. The world form uses `engine.view?.project` if present, otherwise it throws;
      - `end(...ids)`;
    - `errors()`; `page`; `close()`.

    `until` runs its loop inside the page: `for (k < maxSteps) { if (pred()) return k; engine.stepN(1) }`. On failure it throws with the step, the scene and the last events.
  - **Assertions** (async functions that throw `AssertionError`, for use with `node:test`):
