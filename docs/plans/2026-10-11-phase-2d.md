**Architecture:**
- **Commands are the third input layer.** Actions stay levels sampled per step; commands are discrete, typed, plain-JSON messages (`engine.command(type, data)`) queued and delivered in FIFO order by a built-in `lh.commands` system in `input.apply`, right after `lh.input`. Handlers are game-wide (`defineGame({ commands })`, never paused: Tractor Pickup's net messages must keep flowing under a pausing overlay) or scene-scoped (`ctx.command(type, fn)`, removed on exit, skipped while the scene is covered by a pausing overlay, like its controls). Commands issued during a step deliver on the next one.
- **Replays record only what comes from outside the sim.** A recording engine (`record: true`) logs, per step: external ops (UI taps/fills/presses, commands, scene requests made outside a step) and the input snapshot's changes. Sim-issued commands are never recorded (they would double on replay). Headless adds a checksum every 60 steps; `replay(game, tape)` re-feeds the log and names the first diverging checkpoint. Browser recording is out of scope (it needs the frame acks of item 2 on the tape); a recording engine requires step acks.
- **The pointer helper never sees three.js.** `bindPointer` owns the gesture (filters, capture, window routing, tap/press/move coalescing, second-finger cancel) and asks the game's `at(clientX, clientY, event)` for the payload (a ground-plane hit, a ray, an entity hint). The sim does the picking from that payload, so a replay reproduces it. `window.engine.view.project` (which `game.touch` `{ world }` targets already call) is wired from `view.project`, which the game's view half sets.
- **Loading is a scene state, not a scene.** `ctx.load({ build, then, hold, frames, settle })` suspends the scene's `step` hook; in that slot the engine counts ticks and builds once `hold` seconds of engine time have passed and `frames` frames have been presented since the request (Rally's `LOAD_HOLD` hold, generalised: #21, #38). With `settle`, `then` waits until a frame has been presented after the build and no `view.wait` promise is pending. Frame acks: headless and `?lh-test` count every step as a presented frame (deterministic, and the first-tick behaviour matches Rally's 2c counter exactly); a real browser boot counts frames the driver actually rendered, acked at the start of the next tick (the frame drew in the previous rAF, so it has been presented).
- **Strangler order, engine first:** D1–D12 on the engine (each green on the engine, the workspace and Rally), then R1 (Rally adopts) and R2 (Rally minors). Nothing in Pig Pens or Tractor Pickup changes; the plan only checks the new interfaces against their code (see "Next games" below).

### Task D1: Command channel (`src/core/engine.js`, `testing/headless.js`, `src/view/hook.js`, `testing/playwright.js`)

Field note #5 (sim half; D3 adds the pointer half).

**Interfaces:**
- `defineGame` validates `commands`: an object whose values are functions (`defineGame: commands.<type> must be a function`).
- `engine.command(type, data = {})`: `type` must be a non-empty string (`engine: command type must be a non-empty string`); pushes `{ type, data }` and returns the engine. `data` is kept by reference; callers pass fresh plain-JSON objects.
- Built-in system `lh.commands` (stage `input.apply`, `after: ['lh.input']`, registered right after `lh.input`): takes the commands queued before it started (a command issued while delivering waits for the next step) and delivers each in order: first `game.commands[type]?.(engine, data)`, then every open scene from the bottom of the stack up that registered `type` and is not covered by a pausing overlay (`coveredBy(name) === undefined`): `fn(engine, data, ctx)`. A command no handler ran for is dropped and counted in `engine.commands.dropped`.
- A throwing handler: the commands already delivered count, the rest of the batch stay queued (front of the queue) for the next step, and the step finishes and rethrows (the existing step rule).
- `ctx.command(type, fn)` registers on the scene entry; removed on exit (and on a rolled-back enter). Returns a remover.
- `engine.commands`: a persistent object; `pending` and `dropped` are getters; `handles(type)` is true when the game or any open scene (covered or not) handles `type`.
- `h.command(type, data) → h`: throws `headless: no handler for command '<type>'` when `!engine.commands.handles(type)`, else forwards.
- `window.engine.command(type, data)` (calls `after()`); `game.command(type, data)` (Playwright): one `evaluate` that issues the command and renders (`window.engine.render(0)`).

### Task D2: Replay tape (`src/core/engine.js`, `testing/headless.js`, `testing/replay.js`)

Spec T-9 (minimal: record and replay headless; `record: 'on-fail'` file writing stays deferred).

**Interfaces:**
- `createEngine(game, { record: true })`: throws `engine: record needs acks 'steps'` with `acks: 'frames'` (D4 adds the option; until then the check is a no-op guard written now).
- **External** means: not inside a step, not draining a transition, not booting, and not nested inside another recorded op (a depth counter: a tap whose action calls `go` records only the tap).
- Recorded ops (in call order, under the step index `time.step` they precede): `engine.ui.tap/fill` (and D6's `press/release`), `engine.command`, `engine.go/overlay/close/jump`. `data`, `args` and `opts` are stored as JSON copies (`JSON.parse(JSON.stringify(x ?? null))`).
- Recorded input: after `input.apply()` in `lh.input`, the snapshot's values (axes as numbers, buttons as `down`) are compared with the last recorded values (initially all `0`/`false`); changed ones are logged as `input` on the entry for that step.
- `engine.tape()`: `{ v: 1, game: game.id, seed, scene, args, hz: game.sim.hz, log }`, `log` sorted by step, entries `{ step, ops?, input? }`, a deep copy.
- `headless(game, { record: true })`: after each step whose new `time.step % 60 === 0`, pushes `[time.step, checksum(engine.state())]` to `sums`. `h.tape()` returns `{ ...engine.tape(), end: time.step, sums }`; throws `headless: not recording` otherwise.
- `replay(game, tape, { invariants } = {}) → h`: checks `tape.v === 1` (`replay: unknown tape version`) and `tape.game === game.id` (`replay: tape is for '<id>'`); `headless(game, { seed, scene, args, invariants })`; for `k = 0 … end - 1`: applies the entry for `k` (ops through `h`, in order; then `engine.input.hold(input)`), steps once, and when a sum exists for `k + 1` compares it (`replay: checksum differs at step <s> (tape <a>, replay <b>)`). Ops logged at `end` are applied after the last step. Returns `h`.
- The countdown fixture's `race` scene registers `ctx.command('nudge', (e, d, c) => { c.state.x += d.dx; })` in `enter`.

### Task D3: Pointer commands (`src/view/pointer.js`, `src/view/hook.js`, `src/view/boot.js`)

Field notes #5 (pointer half), #8 (pointer filters).

**Interfaces:**
- `bindPointer(engine, { surface, type, at, filter = {}, ignore = 'button, input, [data-lh-ui] *, [data-lh-hold], [data-lh-hold] *', edge = 0, tap = { move: 12, seconds: 0.45 }, press = 0, doc })` → `{ update(dt), dispose() }`. `type` is required (`bindPointer: type required`), `at` must be a function (`bindPointer: at must be a function`).
- `filter.pointerType`: array of accepted `pointerType`s; `filter.button`: array of accepted `button`s. A filtered or ignored pointer is invisible to this binding (it neither starts nor cancels anything).
- **Down:** an accepted `pointerdown` on `surface` (not on `ignore`, `clientX >= edge`) while no pointer of this binding is down calls `at(clientX, clientY, event)`; `null` ignores the press (but the pointer is tracked as down). Otherwise it captures the pointer (`setPointerCapture`), and issues `engine.command(type, { phase: 'down', pointer: pointerId, button, kind: pointerType, ...p })`.
- **Second finger:** an accepted `pointerdown` while another tracked pointer is down cancels the active press (`phase: 'cancel'`, payload from `at` at the last position) and nothing new starts until every tracked pointer has lifted (multi-touch gestures stay the game's).
- **Move:** `pointermove` (routed by `pointerId` on the window, like `bindStick`) only records the latest position; `update(dt)` issues at most one `phase: 'move'` per active press per call when the position changed, and adds `dt` to the press's held time.
- **Up:** `pointerup` issues `phase: 'up'`; then, if the press never moved more than `tap.move` px from its start (straight-line) and its held time is below `tap.seconds` and no `press` fired, `phase: 'tap'` at the same point.
- **Press:** with `press > 0`, `update` issues `phase: 'press'` once when held time reaches `press` and the press never moved more than `tap.move` px.
- **Cancel:** `pointercancel`, `lostpointercapture`, window `blur`/`pagehide` and a hidden page issue `phase: 'cancel'` and end the press.
- `dispose()` removes every listener and ends a press without a command.
- Hook: `installEngine(engine, { …, view })`; `window.engine.view` is `{ get project() { return view?.project; } }`. `boot` passes its `view`. A game's view half sets `view.project = ([x, y, z]) => ({ x, y })` (client px).

### Task D4: Frame acks and the loading protocol (`src/core/engine.js`, `src/view/driver.js`, `src/view/boot.js`, `src/view/hook.js`, `testing/headless.js`)

Field notes #6 (S-6), #21, #38; spec S-6, D-6.

**Interfaces:**
- `createEngine(game, { acks = 'steps' })`; anything else than `'steps' | 'frames'` throws `engine: acks must be 'steps' or 'frames'`. D2's record guard becomes live.
- `engine.time.frames`: presented frames so far (part of the live `time` view).
- `acks: 'steps'`: at the very start of every step the engine counts one presented frame (`time.frames++`, then `onPresent` listeners). `engine.presented()` throws `engine: presented() needs acks: 'frames'`.
- `acks: 'frames'`: `engine.presented()` counts one frame and calls the listeners; nothing else does.
- `engine.onPresent(fn) → off`: `fn(engine)` after each counted frame, in registration order.
- `engine.block(label = '') → release()`: `engine.blocked` counts unreleased blocks; `release` is idempotent.
- `ctx.load({ build, then, hold = 0, frames = 1, settle = false, label = '' })`:
  - `build` is a required function (`engine: load needs a build function`); returns the scene's load record `{ label, then }` (`then` may be reassigned until it runs).
  - Only one load in the engine at a time: a second `ctx.load` from the same scene replaces its pending load (the hold restarts); from another scene it throws `engine: scene '<name>' is already loading`.
  - While a scene has a load, its `step` hook is not called. In its slot (where `lh.scene` would call `step`) the engine: counts a tick; when `ticks · dt ≥ hold − 1e-9` and `time.frames − framesAtRequest ≥ frames`, calls `build(engine, ctx)`. Then, without `settle`, it clears the load and calls `then?.(engine, ctx)` in the same slot. With `settle`, it moves to phase `'settle'` and finishes (clear, `then`) in the first slot where `engine.blocked === 0` and either acks are `'steps'` or a frame has been presented since the build (with step acks this can be the build's own slot).
  - A scene under a pausing overlay has no slot, so its load waits. Exiting the scene drops its load. A throwing `build`/`then` clears the load and rethrows.
- `engine.loading` (persistent): `{ active, scene, label, phase }`, updated in place.
- Driver: after any tick that rendered (`engine.frame` or the manual `engine.render`), the next tick starts with `engine.presented()` when `engine` was created with `acks: 'frames'` (`engine.acks` is exposed read-only for this).
- `boot`: creates the engine with `acks: flags.lhTest ? 'steps' : 'frames'` (tests stay deterministic: `game.until` loops never wait for a rAF); `view.wait(p)` also takes `engine.block('view.wait')` and releases it when `p` settles.
- Hook: `get loading()` (the live object); `settled()` is false while `engine.loading.active`.
- `h.untilLoaded(opts)` = `h.until(x => !x.engine.loading.active, { message: 'untilLoaded', ...opts })`.

### Task D7: Input latch that keeps every tap; capped device time (`src/core/actions.js`, `src/view/driver.js`)

Field notes #41, #44; 2c ledger E1 minors (clearDevice pending latch, latch not preset).

**Interfaces:**
- Each device source keeps, per button, a count of rising edges (`false → true` of that source's own value) since the last `apply()`; the per-source objects are created with every button key preset (no dictionary-mode growth).
- Each button has `owed` presses (capped at 3). `apply()` per button, in order:
  1. a `hold` or `set` value wins as today, and clears `owed`;
  2. else `owed += rises` (all sources); if `owed > 0`: when the snapshot is down, report up (a forced release; `owed` unchanged); else report down and `owed--`;
  3. else the merged level (OR) as today.
  Rises are cleared each `apply()`. Consequences: one short tap = pressed, released (as in 2c, #13); two taps between two applies = pressed, released, pressed, released; a release and re-press while held = released, pressed.
- `clearDevice(source)` removes the source and its unapplied rises.
- Driver: `devices[i].update(dt)` gets `Math.min(dt, engine.game.sim.maxFrame)` (so `view.dt`, a device, is capped too); `engine.frame` still gets the raw `dt` (the loop clamps and counts it).
